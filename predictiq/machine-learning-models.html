01
Supervised classification

Logistic Regression

Business question: Will this customer buy running shoes within 7 days?

Where this model fits best

Use when the target is a binary event (buy / not buy, churn / stay, respond / ignore) and the team values a fast, explainable baseline and interpretable coefficients.

How it works

The model combines feature values with learned coefficients, applies a logistic function and outputs a score between 0 and 1. Calibration must be checked before treating the score as a probability.

Inputs and outputs

Inputs

Purchase outcomes labeled 0/1; historical customer features; time-stamped observation records.

Output

Example: customer RS-1042 receives an illustrative 0.72 purchase score, which requires calibration before interpreting as a 72% probability.

One continuous example: RunSmart

RunSmart: previous orders, cart status, product views and recency are used to score seven-day purchase propensity. The marketing team can rank eligible customers for a controlled test.

Real-world / research example

Real-world industry example: credit-risk and response propensity scoring have long used logistic regression. FICO is a documented commercial scoring pioneer, but this page does not claim FICO's current proprietary score uses this exact algorithm.

✓ Advantages

  • Fast to train, cheap to run and straightforward to explain
  • Strong baseline for binary classification
  • Coefficients and odds ratios support model review

! Limitations

  • Linear relationship in log-odds may miss complex interactions
  • Sensitive to leakage, multicollinearity and badly engineered features
  • Predicted scores can be poorly calibrated on changing populations

How to evaluate it

Evaluate on time-separated test data using precision, recall, ROC-AUC, log loss and calibration; compare with a simple baseline.

02
Supervised classification / regression

Decision Trees & XGBoost

Business question: Which combinations of signals best explain purchase propensity?

Where this model fits best

Use when customer signals interact in nonlinear ways: cart abandonment may mean something different for repeat buyers than for first-time visitors. Single trees are explainable; boosted trees often perform well on structured tabular data.

How it works

A decision tree splits records by feature thresholds. XGBoost combines many shallow trees sequentially, each correcting errors from the earlier ensemble. Inspect feature importance carefully; it is not proof of causation.

Inputs and outputs

Inputs

Structured customer features and historical outcomes; train/validation/test split by time.

Output

Example: customer RS-1042 falls into a high-intent branch. An ensemble outputs a score that must be evaluated and calibrated.

One continuous example: RunSmart

RunSmart: a tree can split first on cart status, then recency, then discount history. XGBoost may learn interactions among views, order frequency, coupon usage and device.

Real-world / research example

Real-world documented example: XGBoost has been widely adopted in data-science competitions and production tabular-data tasks. The source presentation does not identify a verified named retailer deploying XGBoost for customer preference prediction, so RunSmart is a clearly labeled hypothetical application.

✓ Advantages

  • Captures nonlinear patterns and feature interactions
  • Often strong on tabular data with mixed signal types
  • Single trees can be visualized as understandable decision rules

! Limitations

  • Boosted ensembles are harder to explain than a single tree
  • Can overfit or exploit leaked features if validation is weak
  • Feature importance can be misleading, especially with correlated inputs

How to evaluate it

Evaluate on time-separated test data using precision, recall, ROC-AUC, log loss and calibration; compare with a simple baseline.

03
Unsupervised segmentation

K-means Clustering

Business question: Which customers have similar shopping behavior?

Where this model fits best

Use to explore behavioral segments when no class labels are available: loyal runners, bargain seekers, casual browsers and high-value shoppers.

How it works

Choose K clusters, standardize numeric features, then assign each customer to the nearest centroid. Repeat until the cluster assignments stabilize. Interpret the clusters after training; their labels are assigned by analysts, not discovered as ground truth.

Inputs and outputs

Inputs

Scaled numeric behavioral features; careful treatment of outliers and correlated fields.

Output

Example: customer RS-1042 is assigned to cluster 2 ('engaged running enthusiasts'), a human-created descriptive label.

One continuous example: RunSmart

RunSmart: features include orders/year, average basket, discount share, running-category share and visit frequency. One hypothetical cluster contains frequent runners; another contains price-sensitive occasional buyers.

Real-world / research example

Academic example from the uploaded MBA presentation: Anitha & Neelakandan (2024) propose using fitting-room preference data and K-means for fashion customer profiling. This is a proposed research approach, not a verified commercial deployment.

✓ Advantages

  • Does not require purchase labels
  • Simple and fast for exploratory segmentation
  • Can guide distinct marketing strategies and persona research

! Limitations

  • K must be chosen and clusters may not be naturally separated
  • Sensitive to scale, outliers and centroid initialization
  • Clusters do not themselves predict future purchases or establish causality

How to evaluate it

Evaluate on time-separated test data using precision, recall, ROC-AUC, log loss and calibration; compare with a simple baseline.

04
Recommendation systems

Collaborative Filtering

Business question: Which shoes or accessories should we recommend next?

Where this model fits best

Use when many customers interact with many products, creating a useful user–item interaction matrix from purchases, ratings, clicks or viewing history.

How it works

Find similar users or items based on historical interactions; rank products that similar shoppers liked. Item-to-item methods identify products that co-occur in user activity. Modern systems may combine these signals with content and contextual features.

Inputs and outputs

Inputs

User–item purchases, ratings, views, interaction timestamps and optional item metadata.

Output

Example: rank socks B, insoles C and hydration belt D for a customer interested in shoe A.

One continuous example: RunSmart

RunSmart: customers who bought running shoe A also frequently bought sports socks B. The site recommends B to someone viewing A, subject to stock and relevance checks.

Real-world / research example

Documented company example: Amazon's item-to-item collaborative filtering was described by Linden, Smith & York (2003). Netflix also documents personalized recommendations, although its modern production system is not reducible to one algorithm.

✓ Advantages

  • Can discover product affinities without manually specifying every rule
  • Useful for cross-sell, discovery and catalog exploration
  • Item-based methods can scale well with careful engineering

! Limitations

  • Cold-start problem for new users and new products
  • Popularity bias and feedback loops can narrow discovery
  • Sparse interactions can produce weak recommendations

How to evaluate it

Evaluate on time-separated test data using precision, recall, ROC-AUC, log loss and calibration; compare with a simple baseline.

05
Demand forecasting

Time-Series Forecasting

Business question: How many pairs of running shoes should we stock next month?

Where this model fits best

Use when the outcome is a quantity evolving over time: daily sales, weekly orders, seasonal demand, returns or call volumes.

How it works

Model historical demand with trend, seasonality, holidays, promotions and lagged sales. Compare a seasonal-naive baseline with models such as exponential smoothing, ARIMA or machine-learning forecasting; quantify forecast uncertainty.

Inputs and outputs

Inputs

Weekly demand, price changes, promotion calendar, holidays, stockouts and lead times.

Output

Illustrative: forecast 850 pairs versus actual demand 880; the 30-pair gap can create a stockout if no replenishment is available.

One continuous example: RunSmart

RunSmart: the store has weekly sales by shoe size and category. It forecasts demand for the next four weeks, checks lead times and decides replenishment quantities.

Real-world / research example

Industry example: retailers commonly use demand forecasting for inventory planning. The uploaded presentation provides a hypothetical footwear scenario (1,000 traditional order, 850 AI-assisted forecast, 880 actual demand), not a verified named-company deployment of a specific forecasting algorithm.

✓ Advantages

  • Directly supports inventory, staffing and procurement planning
  • Makes trend and seasonality explicit
  • Forecast intervals help manage uncertainty and safety stock

! Limitations

  • Demand shocks and promotions can break historical patterns
  • Stockouts hide true demand unless accounted for
  • Aggregate forecasts may miss size-level or store-level variation

How to evaluate it

Evaluate on time-separated test data using precision, recall, ROC-AUC, log loss and calibration; compare with a simple baseline.
